# 현장 일정 날씨판

오늘 현장 일정과 지역별 날씨를 한 화면에서 보고, 날씨 때문에 주의 · 중지를 검토할 일정을 표시합니다. (교육용 가상 데이터)

## 여는 법
- 아래 Supabase 설정을 마친 뒤 `index.html` 더블클릭 (인터넷 연결 필요)
- 인터넷 : (배포 후 Vercel 주소를 여기에 적기)

## Supabase 설정 (F-06)
1. Supabase 프로젝트의 SQL Editor에서 `setup.sql` 전체를 한 번 실행합니다. `public.wx_tasks` 표, 지역/구분 제약, 공개 조회/추가 정책, 가상 일정 6건이 만들어집니다. 기존 `wx_tasks` 표가 있으면 생성이 중단되며 기존 데이터는 변경하지 않습니다.
2. 프로젝트의 Connect 또는 API Keys 화면에서 Project URL과 publishable 공개용 키를 확인합니다. 기존 프로젝트의 anon 공개용 키도 사용할 수 있습니다.
3. `config.js`의 두 빈 문자열에 주소와 공개용 키를 각각 입력합니다. 키를 채팅에 보내지 않아도 됩니다. 비밀 키, secret 키, service_role 키는 넣지 않습니다.
4. `index.html`을 열거나 배포 주소를 새로고침합니다. 설정이 비어 있거나 SDK/DB 연결에 실패하면 화면 아래에 안내가 나옵니다.

로그인 없는 교육용 표이므로 공개 키를 가진 누구나 가상 일정을 조회·추가할 수 있습니다. RLS와 DB 권한은 조회·추가만 허용하며 수정·삭제는 허용하지 않습니다. `setup.sql`은 앱이 실행하지 않으며 사용자가 SQL Editor에서 실행합니다.

일정은 Supabase에서 읽고 저장합니다. 다른 화면에서 추가한 일정은 새로고침하면 보입니다. 예전 `data/tasks.json`과 브라우저 `wx_added`의 일정은 자동 이관하지 않습니다. 브라우저에 남은 기존 데이터도 삭제하지 않습니다.

## 확인 방법
### 지역별 JSON API (F-07)
Vercel 배포 주소에서 `/api/kma?region=대전`을 열면 대전의 DB 일정, 오늘 기상청 날씨, 일정별 판단을 JSON으로 받습니다. region은 세종·대전·태안·보령 중 하나를 지정합니다. DB의 저장 일정을 조회하며 날씨·판단은 요청할 때 계산합니다.

Vercel 프로젝트 환경변수 `KMA_KEY`에 공공데이터포털 **기상청 단기예보 조회서비스**의 인증키를 설정합니다. 일반 키와 URL 인코딩 키를 모두 지원합니다. 호출할 환경(Production/Preview)에 적용한 뒤 새로 배포해야 합니다. 키를 config.js에 넣지 않습니다. Supabase는 기존 config.js 두 줄의 공개 설정을 서버에서도 함께 사용합니다.

한국 시간 기준 오늘 전체를 비교하기 위해 전날 23시 발표의 오늘 24시간 예보를 사용합니다. 최고 기온은 TMX(없으면 TMP 최댓값), 풍속은 WSD 최댓값(m/s), 강수확률은 POP 최댓값(%)입니다. 응답에 사용한 발표 일시와 출처를 표시합니다. 이 API는 Vercel에서 동작하며 HTML 더블클릭으로는 서버 경로를 실행할 수 없습니다.

날씨 호출 실패 시 `weatherStatus: "unavailable"`, `weather: null`, `warning`과 DB 일정을 반환합니다. 야외·고소는 ‘날씨 확인 전’, 실내는 ‘영향 없음’입니다. DB 조회 자체가 실패하면 502를 반환합니다. 기존 웹 화면은 기존 Open-Meteo 연결을 사용하므로 예보 출처·발표 시점에 따라 API 결과와 차이가 날 수 있습니다.

- T-07: `/api/kma?region=대전`에서 대전 일정만 있고, 각 항목에 weather와 judgment가 있는지 확인합니다.
- T-08: 다른 지원 지역, region 누락·잘못된 값·중복 지정(400), POST 요청(405)을 확인합니다.
- T-09: 키가 없는 Preview 환경에서 일정은 유지되고 날씨 미수신 안내가 나오며 인증키가 응답에 없는지 확인합니다.
